## 四、本次上线修复的问题（真实环境验证发现）

在完成部署后，我做了**带登录态的全业务链路验证**，发现了 4 个编译期发现不了的 bug，已全部修复并重新部署验证通过：

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 学校/标记等接口返回字段全部为 null | 若依默认注释了 `mapUnderscoreToCamelCase`，下划线列无法映射到驼峰属性 | 开启 `mybatis-config.xml` 驼峰映射 |
| 2 | 创建标记/决策返回主键为 null | 注解 SQL 的 insert 未配置主键回填 | 7 个 Mapper 补齐 `@Options(useGeneratedKeys)` |
| 3 | 创建决策报"Data too long" | `fw_decision.decision_type` 列为 `char(1)`，与字符串值 `select/go/buy` 冲突 | 改为 `varchar(10)`（SQL + 线上 ALTER） |
| 4 | 管理端按名称搜索报"no getter keyword" | `FwMark` 实体缺 `keyword` 查询字段 | 实体补 `keyword` 字段 |

> 这些 bug 在 `mvn package` 时完全不会报错，只有在真实运行并调用接口时才暴露——这也是本次坚持做端到端验证的原因。修复后的代码已同步回 `fate-wheel-ruoyi/` 工程和 `fate-wheel-deploy.zip` 发布包。

   ```bash
   mysqldump -ufw_app -pFateWheel@2026 ry-vue > /opt/fatewheel/backup/ry_$(date +%F).sql
   ```
5. **既有站点提醒**：你的 `birthday` 站点占用 80/443，摇去哪用 8090，两者互不影响；若以后想给摇去哪也上 80/443，需要在该站点配置里加 location 转发，我可以帮你做。

## 1. 产品定位与差异化

### 1.1 一句话卖点

> **「把你的收藏夹变成转盘，让命运替你做决定 —— 然后真的出发。」**

「选择终结者」不是又一个决策转盘，而是一个**以地图标记为素材库的真实生活决策引擎**。用户标记想去的地方，转盘从这些真实地点中抽取，决策结果直接关联导航、打卡、分享。

### 1.2 竞品差异化对比



| 维度    | 中午吃啥饭（纯转盘） | 大众点评收藏夹   | 普通地图标记工具 | 小红书探店清单 | **选择终结者**                |
| ----- | ---------- | --------- | -------- | ------- | ------------------------ |
| 决策方式  | 纯文字随机选项    | 无决策功能，仅收藏 | 无决策功能    | 无决策功能   | **转盘从真实标记地点抽取**          |
| 地点数据  | 预设 / 手动输入  | 平台 POI    | 手动标记     | 笔记关联    | **腾讯 POI 搜索 + 用户富信息标记**  |
| 决策后动作 | 无          | 查看详情      | 查看位置     | 查看笔记    | **一键导航 + 打卡 + 决策档案**     |
| 社交属性  | 无          | 无         | 无        | 公开社区    | **≤5 人邀请制小组共享地图**        |
| 多场景覆盖 | 仅 "选什么"    | 无         | 无        | 无       | **选什么 / 去不去 / 买不买三场景**   |
| 数据沉淀  | 无          | 平台数据      | 位置数据     | 内容数据    | **个人决策档案 + 地点图鉴 + 消费统计** |

**差异化核心**：竞品要么只做决策（无真实地点），要么只做地点收藏（无决策机制）。「选择终结者」是**决策引擎 × 地点素材库**的深度融合 —— 标记是为了决策，决策是为了出发。

### 1.3 核心价值主张



1. **对选择困难症**：把 "吃什么" 从纠结 30 分钟变成 3 秒转盘，用随机性消解决策焦虑

2. **对收藏囤积症**：收藏夹里 100 家店永远不去？转盘逼你做选择，标记了就要去

3. **对宿舍 / 朋友组队**：5 人共享 "宝藏地图"，集体标记集体决策，解决 "你们定吧" 的社交僵局

4. **对生活记录者**：每一次决策都被记录，生成个人决策年报 ——"你今年吃了 47 次麻辣烫"

## 2. 三个决策场景交互机制设计

### 2.1 场景一：选什么（转盘从标记地点抽取）

#### 场景描述与用户痛点

> "食堂三楼和校外火锅选哪个？"" 周末去探店，收藏了 8 家店去哪一家？"

用户已经有了候选集合（标记过的地点），但在多个选项间反复纠结。核心痛点是**选项太多、每个都想要、决策成本高**。

#### 交互流程



```
进入"选什么"

&#x20; → 选择筛选条件（分类：美食/玩乐/购物/全部 | 距离：1km/3km/5km/全部 | 状态：想去/已去过）

&#x20; → 系统展示符合条件的标记数量（如"12家店等待你的命运抉择"）

&#x20; → 点击"开始转动"

&#x20; → 转盘动画（3-5秒，带加速→减速→定格）

&#x20; → 结果弹出（地点卡片：名称+图片+评分+距离+地址）

&#x20; → 后续动作：\[立即导航] \[标记为已去] \[换一个（限3次/天）] \[分享决策卡片]
```

#### 决策机制



* **数据源**：用户标记过的地点（可按分类、距离、想去 / 已去过状态筛选）

* **抽取算法**：等概率随机抽取（公平随机，无加权）

* **筛选逻辑**：


  * 按分类筛选：只从 "美食" 类标记中抽

  * 按距离筛选：基于用户当前定位，只抽指定范围内的标记

  * 组合筛选：分类 + 距离同时生效

* **空状态处理**：无符合条件的标记时，引导 "先去标记几个想去的地方吧"，跳转标记流程

#### 上头机制



| 机制        | 设计细节                                          | 心理学原理    |
| --------- | --------------------------------------------- | -------- |
| **转盘动画**  | 自定义转盘，每个扇区显示地点名称 / 图标，旋转时加速→减速→定格，配 "咔哒咔哒" 音效 | 期待感、悬念   |
| **结果揭示**  | 转盘停稳后，地点卡片从中心弹出，带缩放 + 光晕动画，配 "叮！" 音效          | 即时反馈、奖励感 |
| **换一个限制** | 每天限 3 次 "换一个"，用完需等次日或看激励视频（MVP 不接广告，仅次日重置）    | 损失厌恶、稀缺感 |
| **决策仪式感** | 转动前显示 "命运正在为你选择…"，转盘上地点名称快速滚动                 | 仪式感、沉浸感  |
| **结果金句**  | 每次结果配一句随机金句："命运的选择，跪着也要吃完"" 今天它就是你的唯一 "       | 幽默感、分享欲  |

#### 结果展示与后续动作



* **主卡片**：地点名称、封面图、评分、人均价格、距离、地址

* **操作按钮**：


  * 🧭 立即导航（调用微信地图 / 腾讯地图导航）

  * ✅ 标记为已去（更新地点状态，计入 "已拔草"）

  * 🔄 换一个（剩余次数显示）

  * 📤 分享决策卡片（精美图片卡片，含地点 + 金句 + 小程序码）

* **自动记录**：决策结果自动写入决策历史档案

#### 与地图标记的联动



* 转盘的素材池 = 用户的标记地点库

* 决策结果可直接在地图上定位显示

* 标记为 "已去" 后，该地点在转盘中默认排除（可手动切换 "包含已去过"）

* 决策历史中每条记录可点击跳转地图定位

### 2.2 场景二：去不去（利弊天平 + 冲动冷却）

#### 场景描述与用户痛点

> "这家网红店排队 2 小时，值不值得去？"" 朋友约我去蹦迪，但明天有早八，去不去？""这个展览门票 80 元，去不去？"

这不是多选一的问题，而是**二元决策**：去 or 不去。用户的纠结来自利弊交织 —— 想去但有顾虑，不想去但怕错过。纯转盘不适合，因为选项不是等价的，需要**理性辅助 + 心理洞察**。

#### 交互流程



```
进入"去不去"

&#x20; → 输入地点/事件名称（支持从标记地点选择，或手动输入）

&#x20; → 选择决策模式：

&#x20;    \[模式A] 利弊天平——理性分析

&#x20;    \[模式B] 命运硬币——快速决断

&#x20;    \[模式C] 冷静计时器——冲动冷却

&#x20; → 执行对应模式

&#x20; → 得出结果/建议

&#x20; → 后续动作：\[记录决策] \[设为提醒] \[分享]
```

#### 决策机制（三种模式）

##### 模式 A：利弊天平（核心模式）



```
1\. 用户填写"想去的理由"（最多5条），每条可设权重（1-5星）

&#x20;  \- 提供快捷标签：好吃/好玩/便宜/朋友在/打卡/难得一次

2\. 用户填写"不想去的理由"（最多5条），每条可设权重（1-5星）

&#x20;  \- 提供快捷标签：太贵/太远/排队/没时间/累/天气不好

3\. 系统计算：左侧总分 vs 右侧总分

4\. 天平动画：两侧砝码逐渐累加，天平向高分侧倾斜

5\. 结果输出：

&#x20;  \- 差距>30%：明确建议"去吧！理由很充分"或"别去了，顾虑太多"

&#x20;  \- 差距≤30%："势均力敌！建议抛硬币决定"（引导切换模式B）

6\. 附加洞察："你在『太贵』上打了5星——也许可以找个平替？"
```

##### 模式 B：命运硬币（快速模式）



```
1\. 用户输入事件名称

2\. 点击"抛硬币"

3\. 硬币翻转动画（3秒，带旋转音效）

4\. 结果：正面=去，反面=不去

5\. \*\*关键设计\*\*：硬币落下前，弹出一句"在硬币落下前，你心里希望是哪一面？"

&#x20;  \- 用户选择后，硬币结果揭晓

&#x20;  \- 如果用户的期望与硬币结果一致："你的内心已经有答案了"

&#x20;  \- 如果不一致："命运和你想的不一样——但你真的要听命运的吗？"

6\. 这个设计把随机工具变成了\*\*自我认知工具\*\*，不触碰迷信
```

##### 模式 C：冷静计时器（防冲动模式）



```
1\. 用户输入事件名称 + 选择冷静时长（1小时/3小时/24小时）

2\. 启动计时器，显示"冷静中…"

3\. 计时器期间，用户可随时查看，但不能做决策

4\. 时间到，推送通知（需订阅消息）："冷静期结束，现在再想想：去不去？"

5\. 用户重新选择：去 / 不去 / 再冷静一轮

6\. 记录对比：冷静前的倾向 vs 冷静后的决定
```

#### 上头机制



| 机制         | 设计细节                                   | 心理学原理     |
| ---------- | -------------------------------------- | --------- |
| **天平物理动画** | 砝码逐个放上，天平真实倾斜，杆的晃动带物理引擎感               | 视觉满足、因果可见 |
| **硬币悬念**   | 硬币在空中翻转时慢动作，配 "咻 —— 叮" 音效，结果揭晓前的停顿     | 悬念、期待     |
| **内心追问**   | "你希望是哪一面？" 这个问题本身就是上头点 —— 用户会反思自己的真实想法 | 自我洞察、情感共鸣 |
| **冷静倒计时**  | 实时倒计时显示，类似 "待发货" 的期待感，时间到推送唤醒          | 延迟满足、回访触发 |
| **决策对比卡**  | 冷静前倾向 vs 冷静后决定的对比卡片，"你冷静后改变了主意"        | 自我发现、分享欲  |

#### 结果展示与后续动作



* **利弊天平结果**：天平最终状态图 + 总分对比 + 建议文案 + 理由清单回顾

* **硬币结果**：硬币正反面 + 内心期望对比 + 洞察文案

* **冷静期结果**：冷静前后对比 + 最终决定

* **后续动作**：


  * 📝 记录决策（写入决策档案）

  * ⏰ 设为提醒（如 "周六下午出发提醒"）

  * 📤 分享决策卡片

  * 🏷️ 如果是标记地点，可直接更新 "已去" 状态

#### 与地图标记的联动



* "去不去" 可直接从标记地点中选择目标，自动带入地点信息

* 决策结果为 "去" 时，可一键设置导航提醒

* 决策结果为 "不去" 时，可选择 "从想去清单移除" 或 "保留，以后再说"

* 利弊理由中的 "太远"" 排队 "等标签可反向优化标记信息（如给地点加" 排队久 " 标签）

### 2.3 场景三：买不买（价值打分 + 冷静期 + 拥有成本）

#### 场景描述与用户痛点

> "这双鞋 399 元，买不买？"" 这个会员年卡 198 元，值不值？""室友都买了 iPad，我要不要也买？"

这是**消费决策**，核心是价值判断和冲动控制。用户痛点是：想买但怕后悔，不买又怕错过。需要**理性量化 + 冲动拦截**，但必须注意不触碰金融 / 理财类目。

> **合规边界**
>
> ：本场景定位为 "消费决策辅助工具"，不提供投资建议、不涉及理财产品、不做价格预测。所有分析基于用户自行输入的信息，输出为 "参考建议" 而非 "专业判断"。

#### 交互流程



```
进入"买不买"

&#x20; → 输入商品/服务名称 + 价格

&#x20; → 选择决策模式：

&#x20;    \[模式A] 价值打分卡——四维度评估

&#x20;    \[模式B] 拥有成本计算器——单次使用成本

&#x20;    \[模式C] 消费冷静期——延迟决策

&#x20; → 执行对应模式

&#x20; → 得出建议

&#x20; → 后续动作：\[记录决策] \[加入愿望清单] \[分享]
```

#### 决策机制（三种模式）

##### 模式 A：价值打分卡（核心模式）



```
四个维度，每个维度1-5星，用户自评：

1\. 【必要性】你有多需要它？

&#x20;  \- 快捷选项：生活必需 / 提升效率 / 兴趣爱好 / 纯粹想要

2\. 【使用频率】你会多久用一次？

&#x20;  \- 快捷选项：每天 / 每周 / 每月 / 偶尔 / 只用一次

3\. 【性价比】这个价格你觉得？

&#x20;  \- 快捷选项：很划算 / 可以接受 / 有点贵 / 非常贵

4\. 【替代性】有没有平替或可以借用？

&#x20;  \- 快捷选项：无可替代 / 有平替 / 可以借 / 已经有类似的

系统计算综合得分（满分20分）：

\- ≥16分："买！这钱花得值"

\- 11-15分："可以买，但建议等促销/发工资"

\- 6-10分："建议再想想，可能是冲动消费"

\- ≤5分："别买，这钱省下来吃顿好的"

附加洞察：

\- "你在『替代性』上只打了1星——你已经有类似的了，真的需要再买一个吗？"

\- "使用频率『偶尔』+ 价格『非常贵』= 单次使用成本可能很高，试试拥有成本计算器？"
```

##### 模式 B：拥有成本计算器



```
1\. 用户输入：商品价格 + 预计使用时长（月/年）+ 预计使用频率（次/周）

2\. 系统计算：

&#x20;  \- 单次使用成本 = 价格 ÷ (使用频率 × 4周 × 使用月数)

&#x20;  \- 示例：399元的鞋，预计穿2年，每周穿3次 → 399 ÷ (3×4×24) ≈ 1.39元/次

3\. 结果展示："这双鞋每次穿只要1.39元——比一杯奶茶还便宜"

4\. 对比参考：系统提供常见物品的单次使用成本作为参照（如"外卖一次25元""奶茶一次15元"）

5\. 用户判断：这个单次成本你能接受吗？→ 买 / 不买
```

##### 模式 C：消费冷静期



```
1\. 用户输入商品名称 + 价格

2\. 选择冷静时长：24小时 / 3天 / 7天

3\. 启动冷静期，商品加入"冷静清单"

4\. 冷静期内，显示"冷静中…还有XX小时"

5\. 可随时查看，但不能标记为"已买"

6\. 时间到推送："冷静期结束，现在还想买吗？"

7\. 用户决定：买了 / 不买了 / 再冷静一轮

8\. 统计："你今年通过冷静期省下了XXX元"（成就感）
```

#### 上头机制



| 机制         | 设计细节                                                     | 心理学原理           |
| ---------- | -------------------------------------------------------- | --------------- |
| **打分进度条**  | 每打完一个维度，进度条前进，四维全部完成后综合得分 "唰" 地弹出                        | 完成欲、即时反馈        |
| **单次成本惊喜** | "每次只要 1.39 元" 的数字对比，配合奶茶 / 外卖的参照系，产生 "好便宜" 的错觉或 "好贵" 的警醒 | 锚定效应、数字敏感度      |
| **省钱计数器**  | 冷静期放弃的消费累计成 "你省下了 XXX 元"，数字持续增长                          | 成就感、损失厌恶（花了就没了） |
| **维度洞察**   | 针对最低分维度给出犀利点评，"你自己都觉得没必要，还买？"                            | 自我面对、幽默         |
| **决策前后对比** | 冷静前 "超想买"vs 冷静后 "算了" 的对比卡片                               | 自我发现、分享欲        |

#### 结果展示与后续动作



* **价值打分结果**：四维雷达图 + 综合得分 + 建议 + 洞察文案

* **拥有成本结果**：单次使用成本数字 + 参照对比 + 用户最终决定

* **冷静期结果**：冷静前后对比 + 省下金额累计

* **后续动作**：


  * 📝 记录决策（写入决策档案，含消费金额）

  * 💭 加入愿望清单（"以后再说"）

  * 💰 计入 "省下的钱" 统计（如果决定不买）

  * 📤 分享决策卡片

#### 与地图标记的联动



* "买不买" 可关联标记地点（如 "这家店的这件商品买不买"）

* 消费决策记录可按地点统计 ——"你在这家店花了多少钱"

* 决策为 "买" 时，可更新地点的 "已去" 状态

* 价格信息可回写到标记地点的 "价格" 字段，丰富地点数据

## 3. 地图标记功能设计

### 3.1 标记流程（完整交互）



```
触发标记（三种入口）：

&#x20; 入口A：首页底部"+"按钮 → 标记新地点

&#x20; 入口B：地图页长按某位置 → 标记此处
```

> **核心策略：将 "社交" 包装为 "工具协作"，严格限制在≤5 人邀请制小组内，不做公开社区、不做内容广场、不做陌生人社交。**

## 5. 合规专项

### 5.1 社交分享合规方案

#### 好友共享地图的类目规避

**风险**：微信小程序服务类目审核中，"地图标记 + 好友共享" 可能被要求选择 "社交" 类目，而社交类目对个人主体未开放或审核极严。

**规避方案**：



1. **类目选择**：主类目选「工具」，子类目选「效率」或「文档 / 笔记」类（地点清单管理工具）

2. **功能描述**：小程序简介和功能页面中，将小组功能描述为 "多人协作地点清单"" 团队地点管理 "，强调**工具属性**，避免 "社交"" 社区 ""交友"" 聊天 " 等关键词

3. **无即时通讯**：小组内不设聊天功能、不设评论区、不设 @提醒，仅共享地点标记数据

4. **无公开内容**：所有小组为邀请制，无公开搜索、无附近的人、无内容广场

5. **人数硬限制**：≤5 人，从技术层面限制，超出不可创建

6. **审核期隐藏**：首版提交审核时，可考虑将小组功能设为 "灰度开启"（仅特定 openid 可见），审核通过后再逐步放开 ——**需评估此做法的合规风险，建议先咨询微信官方**

#### 分享卡片合规设计



| 分享类型       | 设计                                                    | 合规性           |
| ---------- | ----------------------------------------------------- | ------------- |
| 决策结果卡片     | 用户主动点击 "分享"，生成精美图片卡片（含决策结果 + 金句 + 小程序码），分享到微信聊天 / 朋友圈 | 🟢 用户主动分享，无奖励 |
| 小组邀请卡片     | 组长主动生成邀请卡片，分享给好友                                      | 🟢 用户主动分享，无奖励 |
| 地点标记卡片     | 用户主动分享某个标记地点给好友（"这家店不错"）                              | 🟢            |
| 决策年报卡片（P1） | 用户主动分享年度决策报告                                          | 🟢            |

**禁止的分享行为**：



* ❌ 分享后解锁功能 / 获得积分

* ❌ 集赞、集卡、助力

* ❌ 强制分享才能继续使用

* ❌ 分享到群才能获得奖励

* ❌ "分享给 3 个好友解锁高级皮肤"

#### 组队≤5 人的合规依据



* 微信小程序运营规范中，多人协作工具的合理用户规模通常在小团队范围内

* ≤5 人符合 "宿舍"" 小分队 " 等真实校园场景的自然规模

* 小规模邀请制小组的内容安全风险远低于公开社区

* 建议在小程序后台的 "功能页面" 中，将小组功能归类为 "工具 - 协作效率"

#### 审核范围



| 内容类型 | 字段                   | 审核接口        | 审核时机 |
| ---- | -------------------- | ----------- | ---- |
| 文本   | 地点名称、备注、标签、小组名称、小组简介 | msgSecCheck | 先审后发 |
| 图片   | 地点图片（最多 3 张 / 标记）    | imgSecCheck | 先审后发 |

#### 审核流程



```
用户提交内容

&#x20; → 前端基础校验（长度、格式、非空）

&#x20; → 调用云函数

&#x20; → 云函数调用 msgSecCheck（文本）/ imgSecCheck（图片）

&#x20; → 审核通过：

&#x20;     → 写入数据库

&#x20;     → 返回成功

&#x20; → 审核不通过：

&#x20;     → 不写入数据库

&#x20;     → 返回错误码+违规字段提示

&#x20;     → 前端提示"内容包含违规信息，请修改后重试"

&#x20;     → 记录审核日志（用户id、内容、时间、违规类型）
```

#### 先审后发 vs 先发后审



* **采用先审后发**：所有 UGC 内容必须通过审核后才写入数据库并展示

* **原因**：个人开发者无专职审核团队，先审后发可从源头阻断违规内容，降低平台风险

* **体验影响**：文本审核通常 < 500ms，图片审核 < 2s，用户感知为 "保存中..."，可接受

* **降级方案**：若审核接口超时（>3s），提示 "审核服务繁忙，请稍后重试"，不做放行

#### 违规内容处理



1. **单次违规**：提示修改，不记录处罚

2. **多次违规**：同一用户 24 小时内累计 3 次审核不通过，限制标记功能 24 小时（"你的账号因多次提交违规内容，标记功能暂时限制 24 小时"）

3. **严重违规**：涉及政治、色情、暴力等严重内容，立即限制功能，并保留上报微信官方的通道

4. **举报机制**：小组内成员可举报其他成员的标记，举报后该标记对举报人隐藏，同时进入人工复核队列（个人开发者手动查看）

| ------------------ | ------------ | ---------------------- |
| msgSecCheck 接入（文本） | 0.5 人天       | 云函数封装，前端调用             |
| imgSecCheck 接入（图片） | 1 人天         | 图片上传→云函数调用审核→通过后存存储    |

### 5.3 三个决策场景的合规性

#### 选什么（免费随机转盘）🟢



* **合规判定**：完全合规

* **依据**：


  * 转盘为免费功能，不涉及付费随机

  * 随机性仅用于决策辅助，不涉及抽奖、抽卡

  * 已有 "中午吃啥饭" 等同类工具成功先例

  * 结果为用户自己标记的地点，无平台提供的奖品

* **注意事项**：


  * 不设 "付费增加转盘次数"" 付费解锁稀有选项 "

  * "换一个" 限制为每日免费次数，不做付费购买次数

  * 转盘结果不与任何实物 / 虚拟奖品挂钩

#### 去不去（利弊打分 / 抛硬币 / 冷静期）🟢



* **合规判定**：合规，但需注意措辞

* **依据**：


  * 利弊天平为理性分析工具，基于用户自行输入的信息

  * 抛硬币为娱乐化二元决策，标注 "仅供娱乐"

  * 冷静期为消费决策辅助工具

* **注意事项**：


  * ❌ 不使用 "占卜"" 运势 ""算命"" 风水 ""星座运势" 等词汇

  * ❌ 不提供 "今日宜忌"" 运势指数 " 等迷信功能

  * ✅ 硬币结果标注 "仅供娱乐，决策请结合自身判断"

  * ✅ 利弊分析输出为 "建议" 而非 "结论"，用户拥有最终决定权

  * ✅ 不针对健康、医疗、法律等专业领域给出建议

#### 买不买（价值打分 / 拥有成本 / 冷静期）🟢



* **合规判定**：合规，定位为消费决策辅助工具

* **依据**：


  * 所有分析基于用户自行输入的信息

  * 不提供投资建议、不涉及理财产品、不做价格预测

  * 输出为 "参考建议"，非专业判断

* **注意事项**：


  * ❌ 不涉及股票、基金、理财、保险等金融产品

  * ❌ 不提供 "这个东西会涨价 / 降价" 的价格预测

  * ❌ 不做借贷、分期、信用卡相关建议

  * ✅ 明确标注 "本工具仅为消费决策辅助，不构成任何投资或购买建议"

  * ✅ 拥有成本计算为简单数学运算，无金融模型

  * ✅ 冷静期为行为辅助工具，不涉及资金操作

#### 合规注意事项



1. **不引入代币**：所有商品直接人民币定价购买，不设 "金币"" 钻石 " 等中间货币

2. **不设自动续费**：会员为单次购买（1 年有效期），到期后需手动续费，不设自动扣款

3. **不做付费随机**：所有付费商品为确定性权益，转盘始终免费

## 7. 冷启动与运营路径

### 7.1 校园场景切入

#### 第一切口：中午吃啥（最高频场景）



* **场景**：每天 11:00-12:30，大学生面临 "吃什么" 的终极难题

* **推广方式**：


  * 食堂门口地推（扫码体验转盘，3 秒出结果）

  * 宿舍楼道海报："今天吃啥？让命运决定"

  * 班级群 / 社团群分享决策结果卡片

* **转化路径**：体验转盘 → 发现需要标记地点 → 标记食堂窗口 / 校外店 → 形成使用习惯

#### 第二切口：宿舍组队（天然裂变）



* **场景**：宿舍 4-5 人，"周末去哪玩"" 今晚点什么外卖 "

* **推广方式**：


  * 一个宿舍长创建 "宿舍宝藏地图"，标记全宿舍想去的地方

  * 邀请室友加入（≤5 人刚好覆盖一个标准宿舍）

  * 小组转盘 "宿舍命运决定今晚吃什么"

* **裂变逻辑**：用户主动拉室友（非诱导），每个宿舍就是一个自然传播单元

* **合规性**：纯用户主动行为，无奖励，🟢合规

### 7.2 时间节点运营



| 节点              | 活动         | 形式                           |
| --------------- | ---------- | ---------------------------- |
| 开学季（9 月）        | "新生宝藏地图征集" | 新生标记校园周边，标记最多的前 10 名获徽章（纯荣誉） |
| 考试季（12 月 / 6 月） | "自习室寻宝"    | 标记自习室，转盘决定今天去哪自习             |
| 双十一（11 月）       | "冷静期挑战"    | 用买不买冷静期拒绝冲动消费，晒 "我省下了 XXX 元" |
| 情人节 / 七夕        | "约会地点转盘"   | 情侣 / 暧昧对象共享地图，转盘决定约会地点       |
| 跨年夜             | "年度决策报告"   | 生成年度决策卡片，用户主动分享（P1，配合虚拟支付）   |
| 毕业季（6 月）        | "我的大学宝藏地图" | 毕业生分享 4 年标记的大学地图，引发情感共鸣      |

### 7.3 内容种草

#### 小红书



* **账号定位**："大学生选择困难症救星"

* **内容方向**：


  * "我用转盘决定了一周的午餐，结果…"（实测类）

  * "宿舍 5 人共享宝藏地图，再也不用问 ' 吃啥 '"（场景类）

  * "选择困难症必备！3 个决策工具帮你做决定"（工具推荐类）

  * "大学生周末去哪玩？让命运替你选"（种草类）

* **关键词**：选择困难症、大学生神器、中午吃啥、宝藏地图、宿舍必备、决策工具

#### 抖音



* **内容方向**：


  * 转盘决策过程录屏（带悬念，"看看命运让我吃什么"）

  * 宿舍组队转盘搞笑视频（"命运让我们吃食堂，全宿舍崩溃"）

  * 冷静期挑战（"忍了 3 天没买的鞋，最后…"）

* **形式**：15-30 秒短视频，强节奏，带反转

### 7.4 决策结果分享卡片（自发裂变）



* **设计原则**：卡片足够精美 / 有趣，用户愿意主动分享

* **卡片内容**：


  * 决策结果（"今天命运让我吃：麻辣烫"）

  * 随机金句（"命运的选择，跪着也要吃完"）

  * 地点信息（名称 + 评分 + 距离）

  * 小程序码（扫码也来试试）

* **分享场景**：


  * 分享到宿舍群："今晚就这个了，谁也别改"

  * 分享到朋友圈："今天听天由命"

* **合规性**：用户主动分享，无任何奖励机制，🟢完全合规

### 7.5 冷启动阶段原则



* ❌ 不做付费投放（个人开发者预算有限，且工具类产品靠自然裂变更有效）

* ❌ 不做刷量、刷好评

* ❌ 不做诱导分享、集赞、拉新奖励

* ✅ 靠产品本身的趣味性驱动自然分享

* ✅ 靠校园场景的高频需求驱动口碑传播

* ✅ 靠宿舍组队的天然裂变单元驱动用户增长

* ✅ 前 1000 个用户来自创始人的社交圈（同学、社团、朋友），验证产品后再扩大

## 9. 下一步行动建议

### 开发者现在应该先做什么（按优先级排序）

#### 第 1 步：基础准备（第 1 周，可并行）



| 行动               | 说明                                            |
| ---------------- | --------------------------------------------- |
| 注册微信小程序账号        | 个人主体，名称预审核 "选择终结者"（如被占用可备选 "决策地图"" 选择困难症救星 "） |
| 完成小程序认证          | 支付 300 元 / 年认证费，提交个人身份证                       |
| 完成小程序备案          | 免费，按指引提交备案信息                                  |
| 申请腾讯位置服务 Key     | 个人开发者申请，记录 Key 和配额                            |
| 开通云开发环境          | 在小程序后台开通，选择免费版（个人版）                           |
| **向微信官方核实第 1 项** | 客服 / 社区提问：工具类目下 "多人协作地点清单（≤5 人）" 是否可行         |

#### 第 2 步：核心功能开发（第 2-8 周）



1. **先做地图标记模块**（第 2-3 周）：POI 搜索→选点→填写→保存→列表→详情，这是整个产品的素材基础

2. **接入内容安全审核**（第 3 周）：msgSecCheck+imgSecCheck，在标记保存流程中嵌入

3. **做 "选什么" 转盘**（第 4-5 周）：转盘动画 + 筛选逻辑 + 结果展示，这是最高频场景

4. **做 "去不去" 和 "买不买"**（第 5-7 周）：利弊天平 + 抛硬币 + 价值打分 + 拥有成本

5. **做决策档案和个人图鉴**（第 7-8 周）：数据沉淀 + 地图视图 + 列表视图 + 统计

6. **全程自测**：每个模块完成后立即测试，不积压 Bug

#### 第 3 步：内测与优化（第 9-10 周）



1. 邀请 10-20 个同学 / 朋友内测（覆盖 iOS/Android 不同机型）

2. 收集反馈，重点关注：转盘体验是否流畅、标记流程是否繁琐、决策结果是否有用

3. 修复 Bug，优化体验细节（动画、加载速度、空状态）

4. 准备审核材料：小程序简介、功能页面截图、隐私政策

#### 第 4 步：提交审核与上线（第 11-12 周）



1. 提交微信审核（首版不含小组功能和虚拟支付，纯个人工具，提高通过率）

2. 根据审核反馈修改（可能需要 1-2 轮）

3. 正式发布，在朋友圈 / 班级群 / 社团群宣布上线

4. 开始冷启动：食堂推广 + 宿舍组队 + 内容种草

#### 第 5 步：迭代与变现（上线后）



1. 上线后 2-4 周：上线 P1 功能（连续打卡、分享卡片、冷静期）

2. 上线后 4-6 周：灰度上线小组共享功能（先给活跃用户开放）

3. 上线后 6-8 周：接入虚拟支付，上架商品

4. 持续根据用户反馈迭代，关注数据（日活、留存、标记数、决策数、付费转化率）

### 关键提醒



1. **合规第一**：所有功能设计先过合规检查，宁可功能少一点，也不要因违规被下架

2. **MVP 要克制**：首版只做核心闭环（标记→决策→记录），不要贪多

3. **先验证再投入**：虚拟支付、小组功能、AI 等复杂功能等核心数据验证后再投入

4. **用户反馈驱动**：前 1000 个用户的反馈是最宝贵的，建立用户群，持续沟通

5. **记录决策**：每次产品决策（包括为什么不做某个功能）都记录下来，方便后续回顾
